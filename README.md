# ZKPass

ZKPass is a secure authentication system that uses Zero-Knowledge Proofs (ZKPs) with device-based authentication to verify user identities without revealing sensitive information.

## How It Works (With True ZKP Magic)

### Simple Example: Device + UID Authentication (But with Real ZKP)
Imagine:
- Your **UID** = `Krishna678_INSTA@` (stored on blockchain)
- Your **Device Key** = `secret_device_signature` (stored only on your device)
- **ZKP Circuit** = Circom-based cryptographic proof system

#### Registration Flow:
1. **You Register**:  
   _"I want to create account `Krishna678_INSTA@`"_
2. **System Creates**:  
   - Stores your `UID` on blockchain
   - Generates a unique **device key** for your browser/device
   - Registers your device on blockchain (only device ID + hash, not the key)
   - Gives you a **recovery phrase** to authorize new devices

#### Login Flow:
1. **You Claim**:  
   _"I'm `Krishna678_INSTA@` and this is my authorized device"_
2. **ZKP Proof Generation**:  
   - Your device creates a **Circom circuit proof** using:  
     - Your `device key` (secret, never leaves your device)
     - Your `UID` (public)
     - Current timestamp (prevents replay attacks)
     - **Proving Key** (generated by zk-SNARKs)
3. **Verification**:  
   - Backend checks the proof using **Circom verifier**:
     - Verifies your device is registered on blockchain
     - Validates the ZKP proof with **Verification Key** (generated by zk-SNARKs)
     - Confirms proof was generated recently
   - ✅ Valid? → Logged in! *(No secrets exposed)*  
   - ❌ Invalid? → Rejected

#### Device Revocation & Recovery:
- **Lost Device?** Use your recovery phrase to authorize a new device
- **Revoked Access?** System automatically prompts for recovery phrase
- **Multiple Devices?** Each gets its own device key, all stored on blockchain

#### Why It's Super Secure:
- 🔒 **True Zero-Knowledge**: Circom circuits prove you know the device key without revealing it
- ⚡ **Lightning Fast**: Proof generation <1s, verification <100ms  
- 🛡️ **Mathematically Unfakeable**: Uses zk-SNARKs with Groth16 for bulletproof security
- 🔐 **Device Binding**: Prevents UID hijacking - even if someone knows your UID, they can't login without your device
- 🌐 **Blockchain Persistent**: Device registry survives server restarts, stored on blockchain

*(Uses Circom circuits with snarkjs for industrial-grade Zero-Knowledge Proofs)*

- **Backend**: Express API for handling authentication requests

- Secure user registration with UID and device key generation
- Recovery phrase generation for device authorization

## Getting Started

### Prerequisites

- Node.js (v16+)
- npm or yarn
- Hardhat for blockchain development
- Circom compiler for ZKP circuits

### Installation

1. Clone the repository 

2. Install dependencies for each component:

```bash
# Backend
cd backend
npm install

# Frontend
cd ../frontend
npm install

# Blockchain
cd ../blockchain
npm install
```

3. Set up ZKP circuits:

```bash
cd backend
npm run zkp:build
```

### Running the Application

#### Blockchain (Start First)

```bash
cd blockchain
npx hardhat node
```

In another terminal, deploy the contract:

```bash
cd blockchain
npx hardhat run scripts/deploy.ts --network localhost
```

Copy the contract address to your `.env` file:
```
CONTRACT_ADDRESS=0x5FbDB2315678afecb367f032d93F642f64180aa3
```

#### Backend

```bash
cd backend
npm run dev
```

The backend server will start on http://localhost:3001

#### Frontend

```bash
cd frontend
npm run dev
```

The frontend development server will start on http://localhost:5173

## Authentication Flow

### Registration

1. User enters a unique identifier (UID)
2. System stores UID on blockchain
3. Browser generates a unique device key pair
4. Device public key hash is registered on blockchain
5. System generates a recovery phrase for device authorization
6. User saves the recovery phrase securely

### Login

1. User enters their UID
2. Browser checks if it has a device key for this UID
3. If device key exists:
   - System generates a Circom ZKP proof using the device key
   - Backend verifies the device is registered on blockchain
   - Backend validates the ZKP proof using Circom verifier
   - If valid, user is authenticated
4. If no device key or device revoked:
   - System automatically prompts for recovery phrase
   - User enters recovery phrase to authorize new device

### Device Management

1. **Multiple Devices**: Each device gets its own unique key
2. **Device Revocation**: Devices can be revoked from dashboard
3. **Recovery**: Revoked devices automatically prompt for recovery phrase
4. **Blockchain Storage**: All device registrations stored on blockchain

### Recovery

1. User enters their recovery phrase
2. System generates new device key for current browser
3. New device is registered on blockchain
4. User can now authenticate with the new device

## Security Considerations

- **Device keys never leave the browser** - stored in IndexedDB
- **True Zero-Knowledge Proofs** - Circom circuits prove key knowledge without revealing it
- **Blockchain persistence** - Device registry survives server restarts
- **Device binding** - Prevents UID hijacking attacks
- **Automatic recovery flow** - Seamless re-authorization for revoked devices
- **Rate limiting** - Protection against brute force attacks
- **Recovery phrases should be stored securely** by users

## ZKP Technical Details

- **Circuit Compiler**: Circom 2.0
- **Proof System**: Groth16 zk-SNARKs
- **Library**: snarkjs for proof generation and verification
- **Performance**: <1s proof generation, <100ms verification
- **Security**: Cryptographically secure with trusted setup
